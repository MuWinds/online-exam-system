## 6. 统计数据策略

| 候选方案 | 说明 | 状态 |
| --- | --- | --- |
| 实时聚合 | 从成绩或答卷表实时计算人数、平均分、及格率和分布 | 待全组确认 |
| 缓存结果 | 对已发布考试缓存统计结果，成绩变更后失效 | 待全组确认 |
| 统计快照表 | 发布成绩时生成快照，适合固定报表但增加一致性成本 | 待全组确认 |

初期建议优先实时聚合，数据量或性能确有需要后再增加缓存或快照；该建议仍为 **待全组确认**。

## 7. 一致性与安全候选规则

| 规则 | 状态 |
| --- | --- |
| 保存答案仅允许答卷所有者且答卷处于可作答状态 | 待全组确认 |
| 交卷、状态迁移和自动评分在明确事务边界内完成 | 待全组确认 |
| 重复交卷返回同一最终状态，不重复累计成绩 | 待全组确认 |
| 标准答案在考试结束或权限允许前不得暴露给考生端 | 待全组确认 |
| 评分变更保留操作人、时间和必要的审计信息 | 待全组确认 |
| 成绩统计只纳入满足既定状态条件的记录 | 待全组确认 |

## 8. 全组评审清单

- 与用户、考试、试卷和试题模块对齐真实表名、主键类型及删除策略。
- 是否允许补考或多次作答；这将决定 `(exam_id, user_id)` 是否唯一。
- 答案采用 JSON、文本还是按题型拆表。
- 是否保存试题、分值和标准答案快照。
- `exam_result` 是否独立建表，还是由 `exam_attempt` 直接承担成绩查询。
- 分数精度、舍入规则、及格线来源和排名规则。
- 枚举存储方式、逻辑删除、乐观锁、外键和审计策略。
- 统计口径、缓存策略和成绩更正后的重算机制。
