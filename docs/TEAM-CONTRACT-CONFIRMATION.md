2026-10-28确认补记：用户转述任务1回复“没问题”，任务2回复“看都没啥问题”并计划提供数据库和Docker Compose；任务3负责人已授权实施。下面是原始确认基线，表内“待全组确认”为发出时状态。公共基线已获无异议回复，新增详细字段和适配接口仍需联调核对，不代表其他成员已交付模块。

## 1. 确认目的

本文用于三名成员在开始跨模块开发前确认统一标准。本文给出一套可直接执行的默认方案，成员无需重新设计全部内容，只需逐项确认或提出明确修改意见。

确认完成前，本文内容属于 **待全组确认**；全组确认后，应同步更新 `API-CONTRACT.md`、`DATABASE-CONTRACT.md`、项目 README 和总 SQL 脚本。

## 2. 确认方式

每名成员应按照以下格式回复：

```text
任务1：确认

或

任务1：第 4 项建议将 DECIMAL(6,2) 改为 DECIMAL(8,2)，原因是……
```

提出修改时必须写明：

1. 对应编号。
2. 原方案。
3. 建议方案。
4. 修改原因。
5. 受影响的模块。

全组成员均回复“确认”或对修改方案达成一致后，才能将对应项目标记为“已确认”。

## 4. 默认接口标准

| 编号 | 项目 | 默认方案 | 状态 |

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

```json
{

  "message": "success",

    "total": 0,
    "page": 1,
```

## 8. 模块输入与责任

### 8.1 任务1需要提供

- 当前用户 ID、姓名、角色和登录 Token。
- 用户、角色、题目和选项的最终字段定义。
- 题型、题干、选项、分值和服务端标准答案格式。
- 登录、当前用户和题目查询接口。

### 8.2 任务2需要提供

- 试卷、试卷题目关系和考试的最终字段定义。
- 试题顺序、卷面分值和试卷总分。
- 考试 ID、试卷 ID、开始时间、结束时间和考试状态。
- 试卷查询、考试查询及考试发布接口。
- 合并并维护全组确认后的总 SQL。

### 8.3 任务3负责

- `exam_attempt`、`exam_answer`、`exam_score` 的字段草案。
- 在线答题、保存答案、交卷、自动评分和成绩查询。
- 成绩统计、整体测试、缺陷记录和回归结果。
- 发布考试到交卷评分主流程的活动图或时序图。
